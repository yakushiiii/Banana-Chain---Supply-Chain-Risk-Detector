# Add a reproducible comparison run for the fixture and real test repos

## Description
Serves US-102 (compare Banana Chain with other dependency scanners). This task defines which repos and criteria the comparison uses, and adds a script that runs Banana Chain's pipeline (Syft, then Grype) on those repos and prints one results row per repo. It also adds tests so a teammate can check the comparison setup works.

Out of scope: running Trivy or OSV-Scanner from the script (those are run by hand from the steps in `docs/comparison.md`), filling in the final results table, and any change to the app, API or frontend.

## Specs
- `docs/comparison.md` lists the four fixture repos in `tests/fixtures/repos/` (`js-app`, `py-app`, `go-app`, `empty-repo`) and two real repos, `pallets/flask` and `gin-gonic/gin`, each pinned to a release tag and commit SHA.
- `docs/comparison.md` lists the criteria: components found, vulnerabilities found, severity data, speed, and setup effort. It also gives install, run and results steps, including `grype db update` and `python scripts/run_comparison.py`.
- `scripts/run_comparison.py` exposes:
  - `FIXTURE_NAMES` and `REAL_REPOS` (name mapped to git URL, tag and commit SHA).
  - `count_components(sbom)`: number of entries in `components`; a missing `components` key counts as 0.
  - `count_severities(findings)`: counts per Critical, High, Medium, Low, Negligible and Unknown. A missing or unrecognized severity counts as Unknown.
  - `run_pipeline(path, runs)`: runs `run_syft.generate_sbom` and `run_grype.scan_sbom` on a folder and returns a dict with `components`, `vulns`, `severities`, `seconds` (median of `runs`) and `packages_with_vulns`.
  - `main(argv)`: prints a markdown table header and one row per fixture, returns 0. With `--real` it also clones and scans the pinned real repos and fails if a commit SHA does not match.
- The row format is `| <repo> | Banana Chain | <components> | <vulns> | <crit / high / med / low / neg / unk> | <seconds> | |`.
- `tests/test_comparison.py` holds the tests. Tests that need the `syft` or `grype` command are skipped if it is not installed.

## Requirements
- No new runtime dependencies. The script reuses `app/run_syft.py` and `app/run_grype.py`.
- Do not change code under `app/`.
- The script must not run anything from the scanned repos.
- Real repos must be pinned to a tag and commit SHA so results do not change over time.
- Existing tests must keep passing.

## Acceptance criteria
1. `docs/comparison.md` lists all four fixture repos and both real repos, with each real repo's tag and commit SHA matching `REAL_REPOS` in the script.
2. `docs/comparison.md` lists all five criteria: components found, vulnerabilities found, severity data, speed, and setup effort.
3. `docs/comparison.md` includes the `python scripts/run_comparison.py` command and `grype db update`.
4. `count_components` returns 0 when the SBOM has no `components` key and the entry count otherwise.
5. `count_severities` counts each severity level correctly and counts a missing or unrecognized severity as Unknown.
6. `run_pipeline` returns the component count, vulnerability count, severity counts and vulnerable package names from the Syft and Grype results.
7. `run_pipeline` on `empty-repo` returns 0 components and 0 vulnerabilities.
8. `run_pipeline` on `py-app` reports `requests`, `urllib3` and `PyYAML` as having vulnerabilities.
9. `main(["--runs", "1"])` returns 0 and prints a results row for every fixture repo.
