# Validate and normalize public GitHub repository URLs

## Description
Serves User Story #86 (Scan projects and detect supply chain risk vulnerabilities / Ingestion #16). This task implements strict GitHub repository URL validation and normalization in `app/pipeline/ingest/url.py`. It guarantees that only valid, public GitHub repository URLs are accepted, rejects malicious, lookalike, or malformed URLs, and returns normalized repository metadata. It also raises a typed `InvalidRepoUrl` exception that FastAPI maps to an HTTP 422 response.

Cloning the repository (issue #18), file upload ingestion, and running Syft SBOM generation are out of scope.

## Specs
- Implement `validate_and_normalize_github_url(raw_url: str) -> tuple[str, str, str]` (returning `(normalized_url, owner, repo)`) in `app/pipeline/ingest/url.py`.
- URL parsing rules using `urllib.parse.urlsplit`:
  - Scheme must be strictly `https`. Reject `http`, `git`, `ssh`, or missing schemes.
  - Host must be exactly `github.com` (case-insensitive). Lookalike hosts such as `github.com.evil.com`, `evil-github.com`, or raw IP addresses must be rejected.
  - Reject URLs containing embedded user credentials (`https://user:pass@github.com/...`).
  - Reject URLs with explicit port numbers (`https://github.com:443/...`).
  - Reject URLs containing query parameters (`?ref=main`) or fragments (`#readme`).
  - Reject URLs containing path traversal (`..`) or empty path segments (`//`).
- Path validation:
  - Path must consist of strictly `/<owner>/<repo>`.
  - `owner` must match regex `^[A-Za-z0-9-]{1,39}$` (valid GitHub username/org format).
  - `repo` must match regex `^[A-Za-z0-9._-]{1,100}$` (valid GitHub repository name format).
  - Optional `.git` suffix is stripped from the normalized URL and repo name.
  - Optional trailing slash is stripped.
  - Paths referencing subdirectories or branches (e.g. `/tree/<branch>` or `/blob/<commit>`) are rejected.
- Normalization:
  - Output URL is formatted strictly as `https://github.com/<owner>/<repo>`.
  - Normalizing an already-normalized URL is idempotent and returns the identical string.
- Error handling:
  - Invalid inputs raise a custom exception `InvalidRepoUrl(Exception)` with a descriptive error message.
  - In `app/main.py`, an exception handler maps `InvalidRepoUrl` to an HTTP 422 Unprocessable Entity status with `{ "detail": "<error message>" }`.
- Test suite in `tests/test_url_validation.py` contains at least 15 parametrized test cases covering valid formats, lookalikes, credentials, non-https schemes, and invalid path structures.

## Requirements
- Use standard library `urllib.parse` and `re`. No external URL parsing packages.
- Must integrate cleanly with FastAPI exception handling in `app/main.py`.
- All existing tests in `tests/` and `backend/tests/` must continue to pass without regression.

## Acceptance criteria
1. Valid GitHub URLs (with or without trailing slash or `.git`) return the normalized URL, owner, and repository name.
2. Normalizing an already-normalized URL returns the same normalized URL value.
3. Non-https schemes (such as `http://` or `git://`) raise `InvalidRepoUrl`.
4. Lookalike hosts such as `github.com.evil.com` raise `InvalidRepoUrl`.
5. URLs containing credentials, explicit ports, query strings, or `/tree/` branch paths raise `InvalidRepoUrl`.
6. When an invalid URL is supplied to the FastAPI endpoint, the application responds with HTTP 422 and a descriptive JSON detail.
7. At least 15 parametrized test cases in `tests/test_url_validation.py` assert valid and invalid cases.
