# Implement Scan Status Updates in the GUI

## Description

Serves User Story #80 by implementing real-time scan status updates in the GUI. This task integrates Celery and Redis to manage background repository scanning jobs and allows users to track scan progress through the frontend.

The frontend polls the backend API for job status updates and displays the scan lifecycle states: Queued, Running, Done, and Failed. This provides users with visibility into the progress and outcome of repository scans without needing to wait for the request to finish.

## Specs

- In `app/workers/celery_app.py`:
  - Configure Celery to use Redis as the message broker and result backend.
  - Implement the background repository scanning task.
  - Report task progress and status updates during scanning.
- In `app/main.py`:
  - Update `POST /api/scan` to submit repository scans as background Celery tasks.
  - Return a scan ID and task ID when a scan is successfully queued.
  - Implement `GET /api/scan/{task_id}` to retrieve the current task status and result.
  - Handle task submission errors when the queue is unavailable.
- In `frontend/src/api/scan.ts`:
  - Implement API functions for submitting scans and retrieving scan status.
- In `frontend/src/App.tsx`:
  - Display scan status updates in the GUI.
  - Poll the backend for task status updates every 5 seconds.
  - Display the appropriate status: Queued, Running, Done, or Failed.
  - Display scan results when the task completes.
  - Display an error message when the task fails.
- In `docker-compose.yml`:
  - Configure Redis and the Celery worker services.
- In `requirements.txt`:
  - Include the Celery Redis dependencies.
- In `tests/test_scan_status.py`:
  - Add automated tests for queued, running, completed, and failed scan statuses.

## Requirements

- Built using the existing FastAPI backend and React/TypeScript frontend.
- Use Celery for background task processing and Redis for task queuing and status storage.
- Use HTTP polling to retrieve scan status updates.
- Preserve existing scan functionality and the Jinja template route `/results`.
- Ensure task failures are reported to the frontend.

## Acceptance criteria

1. Repository scan submissions are queued as background Celery tasks.
2. The API returns a task ID that the frontend can use to track the scan.
3. The scan status endpoint correctly reports Queued, Running, Done, or Failed.
4. The frontend polls the status endpoint every 5 seconds.
5. The GUI displays the current scan status to the user.
6. Completed scans display their results.
7. Failed scans display an appropriate error message.
8. Redis and the Celery worker are configured to support background scanning.
9. Automated tests cover the scan status lifecycle.
